# データ設計・DB運用

Go の GORM モデルおよび DB 関連コードから確認できる現状と、今後の運用ルールをまとめています。このディレクトリをデータ設計ドキュメントの正本とし、アプリケーション本体と同じ `cellar-app-backend` リポジトリで管理します。

| 文書 | 役割 |
|---|---|
| [データモデル](./data-model.md) | エンティティ、テーブル間の関係、所有と削除の考え方 |
| [スキーマ管理方針](./schema-management.md) | GORM モデルと `AutoMigrate` によるスキーマ変更ルール |
| [DB運用手順](./database-operations.md) | 接続、バックアップ、検証、復元の作業手順 |
| [データディクショナリ](./data-dictionary.md) | 各テーブルとカラムの業務上の意味 |

## 調査範囲と未確認事項

- 実装の根拠はバックエンドの `model/model.go`、`database/`、`dto/`、テストコード、および DB を含む Compose 設定と初期復元スクリプトです。
- 2026-10-13 に利用者から提供された `psql` の照会結果により、`cellar_app.public`（`localhost:5432`、PostgreSQL 17.6）と GORM モデルを照合しました。モデルとの差分のみを[データモデル](./data-model.md)と[データディクショナリ](./data-dictionary.md)に記載し、記載のない確認対象は照合時点でモデル定義と整合していたものとして扱います。実データの内容やバックアップ状態は確認していません。
- バックエンド既存資料には、2026-10-12 に本番 PostgreSQL 17.6 でスキーマ作業を行い、別環境でバックアップ復元検証を実施した記録があります。これは既存資料上の履歴であり、バックアップが現在も取得・検証されていることを示すものではありません。
- データベース上の構造は既存資産・運用アプリケーションを含む可能性があります。GORM モデルにないテーブルやカラムを、未使用と判断したり削除したりしないでください。

## 記述上の区別

- 「現状」は確認したソースコードや既存設定に記載された内容です。
- 「運用ルール」「推奨」は今後の開発・運用で適用する方針です。
- GORM タグから型や NULL 可否を説明する箇所は、コード上のモデル定義です。実 DB の物理スキーマとの確認結果と差異は[データモデル](./data-model.md)および[データディクショナリ](./data-dictionary.md)に記載し、ほかの DB 環境へ一般化しません。
